# PRD: 智能书签专属目录

## Goal

在 Chrome 原生书签中建立独立、用户可自定义的 AI 整理空间。AI 只读取和移动该根目录及其后代中的书签；其他书签保持不受影响。

## Background and confirmed facts

- 当前项目已实现 Chrome MV3 新书签监听、AI/规则分类、动态读取文件夹树、自动移动与 Review 确认、历史扫描与批量撤销、手动摘要标签。
- 当前实时整理默认处理 Chrome 内置书签根目录的直接子项；`forceOrganize` 可扩大到其他用户目录。分类请求使用当前书签元数据和整棵树的文件夹清单。
- 当前没有智能根目录 ID、首次安装目录初始化或目录内数据隔离；没有网页正文读取。
- 当前 Chrome Bookmarks API 服务已有树/文件夹枚举、路径、移动、创建和 managed 节点检查；持久化经 `StateRepository` 写入本地 `chrome.storage.local`。
- 用户希望专属目录名称体现 Chrome 当前登录账号。Chrome Extensions `identity.getProfileUserInfo()` 只提供主账号 email 和 id，不提供显示名称；需要 `identity.email` manifest permission，未登录或无权限时字段为空。扩展在 service worker 中调用该 API，取 email 的 `@` 前本地部分。
- 用户接受用主账号邮箱 `@` 前的部分作为根目录名；未登录时使用 `bookmark`。最终根目录名采用“`<本地部分> 的智能书签`”格式，例如“`yuan 的智能书签`”。
- 根目录固定创建在 Chrome 原生“书签栏”下；首次只创建一级默认分类：`📥 待分类`、`💼 工作`、`🚀 项目`、`🧑‍💻 开发`、`📚 学习`、`🔬 研究`、`📰 阅读`、`🛠️ 工具`、`🎨 灵感`、`🌿 生活`、`🗄️ 归档`。
- 根目录 ID 写入 `chrome.storage.local` 的持久化状态；初始化通过已保存 ID 和当前书签树双重校验，避免重复创建。
- 历史任务 `10-09-ai-bookmark-manager` 明确采用“不读网页正文、不申请网站访问权限”的隐私边界；本任务继续保持该轻量边界。
- 仓库近期基础验证通过：`pnpm typecheck`、`pnpm test --run`（92 tests）、`pnpm build`。Chrome 手工冒烟未执行。

## Requirements

- R1. 首次安装时在 Chrome 原生“书签栏”中创建一个按账号命名的专属根文件夹及确认的一级默认子文件夹；保存根文件夹 ID。重复安装/启动不得重复创建。
- R2. 仅当新增书签位于专属根目录或其后代时触发自动分类。书签在根外时，不分类、不移动、不删除，也不把其标题/URL发送给 AI。
- R3. 每次分类只向 AI 提供该书签的允许元数据，以及专属根目录子树内的文件夹 ID、名称和路径。动态跟随用户对目录的新增、删除、重命名和嵌套调整。
- R4. 只有实时验证属于专属根子树的目标目录，才允许自动移动或经用户确认后移动；新目录建议的父级也必须在该子树内。拒绝建议、分类失败或目标失效时，书签留在原位。
- R5. 异步分类期间如用户移动书签，处理流程不得覆盖用户的新位置；移动前重读书签和目录树。
- R6. 保留现有 AI 配置、置信度/确认模式、Review、撤销和历史扫描能力；历史扫描范围同步限制为专属根子树。
- R7. 不建立独立书签数据库；Chrome Bookmarks API 是书签和目录的唯一事实来源，扩展只在 `chrome.storage.local` 保存必要配置与已有任务状态。
- R8. 只使用书签标题、URL、域名和当前目录信息分类；不读取网页正文，不新增网页访问权限。
- R9. 专属根目录名使用“邮箱本地部分 + 的智能书签”；未登录、权限未授予或邮箱不可用时使用“`bookmark 的智能书签`”。
- R10. 首次初始化根目录下的轻量默认分类布局；分类器随后以实时目录树为准，不依赖固定名称。
- R11. 账号名只通过 `chrome.identity.getProfileUserInfo()` 获取；API 不返回显示名时不额外申请账号系统或网页权限，按邮箱本地部分/`bookmark` 回退规则生成目录名。

## Acceptance Criteria

- AC1. 首次安装后，书签栏下只出现一个专属根目录和确认的一级初始子目录；根目录名遵循邮箱本地部分/`bookmark` 回退规则；重启或重复安装事件不产生重复目录；根目录 ID 可恢复。
- AC2. 根目录内新增书签进入现有持久化分类流程；根外新增书签不产生分类任务、AI 输入或书签变更。
- AC3. AI 可选择的现有目录和新目录父级均只来自当前专属子树；模型返回根外、managed、已删除或伪造 ID 时不移动、不创建目录。
- AC4. 新建、删除、改名、嵌套文件夹后，后续分类读取最新结构并正确映射路径/ID；无需重启扩展或维护平行目录副本。
- AC5. 分类等待期间用户手动移动书签时，自动流程不把书签移回或移到建议目录；失败状态可见且书签保留。
- AC6. 历史扫描只枚举专属子树中的可整理 HTTP(S) 书签；审批与撤销继续尊重 live-state 检查和现有撤销保护。
- AC7. 现有自动整理、Review、设置、摘要标签行为通过回归验证；`pnpm typecheck`、`pnpm test --run`、`pnpm build` 通过。

## Out of Scope

- 跨浏览器同步、服务端书签库、账号系统或云端索引。
- 插件内替代 Chrome 原生书签管理器；子目录编辑沿用 Chrome 原生书签 UI。
- 自动删除、合并、重命名用户目录或移动根目录外项目。
- 网页正文抓取、页面内容索引和新增网页访问权限；保持产品轻量化。
