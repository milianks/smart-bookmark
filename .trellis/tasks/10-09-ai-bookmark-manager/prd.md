# AI Bookmark Manager — P0 MVP

## Goal and user value

用户继续使用 Chrome 原生收藏按钮；配置好自己的 API Key 后，扩展自动识别新书签并归档到合适的现有目录。只有需要新建目录或分类不确定时才请用户确认。所有改动可追踪、可撤销，且不上传完整书签库或网页正文。

## 已确认的范围与约束

- 本任务实现下面的 P0；P1/P2 保留为路线图，不并入本次验收。
- 仓库目前没有应用代码、包清单、测试或产品文档，只有 Trellis 初始化文件。
- 使用 pnpm、WXT、React、TypeScript、Tailwind CSS、shadcn/ui、Chrome Manifest V3、Chrome Bookmarks/Storage/Notifications APIs、Zod 和 Vitest。
- 最低支持 Chrome 134，以使用 `BookmarkTreeNode.folderType` 识别内置书签根目录；不按本地化名称或硬编码 ID 猜测根目录。
- API Key 是启用自动整理的必填项。未配置时扩展显示设置引导，新书签原位保留并可在设置完成后恢复处理；P0 不提供无 Key 的纯本地模式。
- API Key 配好后，先用本地分类缓存和确定性规则处理高置信度书签；只有缓存/规则无法可靠分类时才请求 OpenAI 兼容 API，以控制成本。分类结果注明来源。远端 AI 调用失败、超时或返回无效结构时，书签留在原位并记录/提示失败。
- 采用用户已选择的 A 规则：默认只自动整理直接保存在 Chrome 内置根目录的书签；保存到用户自建文件夹内的书签原位保留；强制整理设置可以覆盖。Chrome API 无法区别用户是否主动选了某个内置根目录，这一边界在 UI/README 中说明。
- 不需要后端、账号、数据库、云同步或分析 SDK。网页正文读取、历史书签批量整理和其他浏览器支持均不属于本次 P0。

## P0 需求

### 智能收藏（P0 #1–5）

- 监听 `chrome.bookmarks.onCreated`，只处理包含有效 HTTP(S) URL 的普通书签；跳过文件夹、其他 URL scheme 和已有历史书签。
- 获取书签标题、URL 和域名；新增后自动启动分类，允许系统自动移动高置信度结果。
- 默认尊重书签所在的用户自建文件夹；强制整理开关可覆盖。Chrome API 无法识别用户是否主动选择了某个内置根目录，按已确认的根目录策略处理。

### AI 智能分类（P0 #10–15）

- 根据标题、URL 和域名分析主题及置信度，并结合当前目录和现有目录的 ID/名称/完整路径；默认不发送其他书签的标题/URL或网页正文。
- API Key 配置完成后，先查本地分类缓存和确定性规则；达到阈值的结果可直接使用，只有无法可靠分类时才调用 OpenAI 兼容 API，以控制成本。缓存、规则和 AI 的分类来源分别记录并显示。
- 输出严格校验的 `action: "move" | "suggest_folder" | "keep"`、置信度和原因，以及需要时的目标目录 ID 或新目录名称/父级 ID。AI 只提供建议，不调用 Chrome API。
- 优先匹配已有目录；无合适目录时建议名称和所属层级，避免同义目录和无必要的层级。所有目标/父级 ID、目录类型和当前书签位置都必须对照最新真实书签树验证。
- 远端 AI 调用失败、超时、权限不足或返回无效结构时，书签留在原位并记录/提示失败；不把失败静默变成移动。

### 自动归档、确认与撤销

- 默认置信度阈值为 `0.85`，可配置。自动模式下，高置信度的现有目录建议可以自动移动；确认模式下所有移动都需确认；新目录永远需要确认。
- 对低置信度建议保留原位并加入待审核项。无匹配目录时，推荐新目录名称和父级位置，用户确认后创建并移动，拒绝后保持原位。
- 默认尊重用户保存到自建文件夹的选择；支持强制整理模式覆盖此约定。
- 每次移动记录原文件夹、目标文件夹、书签和操作时间；支持撤销最近一次自动移动。绝不自动删除书签或文件夹。

### 文件夹服务（P0 #20–22）

- 封装完整书签树读取、文件夹枚举/路径/ID 查询、存在性验证、移动、创建等 API，业务逻辑可通过 Mock 测试。

### 通知与交互确认（P0 #61–65）
- 使用 Chrome Notifications API 提醒待确认目录、低置信度建议和分类失败；可单独开启收藏成功提示（默认关闭），总开关关闭时不发送通知。点击审核通知进入扩展内 Review 页面，不依赖 Side Panel。
- Review 展示书签标题/URL、推荐目录、原因和分类来源，并提供适用的“移动到推荐目录”或“创建目录并归档”按钮，以及“保留原位”。
- Popup 展示自动整理开关、API 配置状态、最近书签/操作、待处理数、撤销最近移动入口和设置入口。
- 所有 UI 使用中文，支持浅色/深色主题。

### AI 配置（P0 #75–80）

- Settings 配置自动整理开关、API 地址/模型/必填 API Key、AI 接口连接测试、自定义置信度阈值、自动模式/每次确认模式、强制整理、通知选项和操作日志。明确警告浏览器扩展本地存储不是高安全级别的密钥管理方案。

### 隐私、安全与可靠性（P0 #85–90）

- 必要权限限于 `bookmarks`、`storage`、`notifications`、`alarms`；无静态全站 host 权限。自定义 API 地址通过可选 host permission，在用户操作中只请求该 API 来源。非回环地址只允许 HTTPS。
- 设置、缓存、待处理任务和操作日志留在 `chrome.storage.local`。密钥不写入代码、日志、通知或 Git。
- 标题和 URL 作为不可信文本处理，防提示注入；React 只按文本渲染用户/AI 内容。请求有超时和大小限制。
- 后台监听器同步注册；导入期间抑制新建事件分类，导入状态持久化并可超时恢复。待处理任务使用书签 ID 幂等，Worker 重启后恢复，失败有限重试。未配置 API Key 的新任务等待设置完成，只处理扩展安装后的新增事件，不扫描历史书签。
- 处理目标目录删除、书签被用户移动、重复事件和并发请求时安全降级；不因事件重放重复创建建议或移动书签。
- 交付中文 README，说明启动/构建、Chrome 加载未打包扩展、API 设置、权限、隐私、API Key 风险和已知限制。

## 验收标准

- [ ] `pnpm dev` 可启动 WXT Chrome 开发构建，`pnpm build` 生产构建成功；提供 `pnpm typecheck` 和 `pnpm test`。
- [ ] API Key 未配置时自动整理不可运行，界面引导设置；配置后可测试连接。构建和测试使用 Mock，不依赖用户提供真实 Key。
- [ ] 本地缓存/规则在远端请求前运行；只有不能可靠分类时才调用模型。UI/日志准确区分缓存、规则和 AI 来源。
- [ ] 新建书签只处理一次；符合根目录默认规则的高置信度匹配移入有效现有目录并记录撤销信息；嵌套用户文件夹的书签保留，强制模式可覆盖。
- [ ] 无匹配目录或低置信度时创建待确认建议；确认后安全创建/移动，拒绝后书签保持原位。确认模式下高置信度移动也必须先确认。
- [ ] AI 超时、接口失败、Schema 错误、Key/权限错误、目标目录删除、来源书签被用户移动或重试耗尽均不错误移动/丢失书签，并向用户呈现可理解状态。
- [ ] Chrome 原生导入不造成大量连续 AI 请求；重复事件、并发处理和 Worker 重启不会造成重复移动/建议，待办可恢复。
- [ ] Worker 重启后恢复持久化队列；未配置 Key 时新增书签保持原位并等待配置，配置后只处理这些新任务，不扫描历史书签；失败按有限次数重试。
- [ ] 可以撤销最近一次自动移动并恢复原父目录。
- [ ] Popup、Settings、Review 具备上述交互；设置保存在本地；通知总开关和可选收藏成功提示有效，点击审核通知打开 Review。
- [ ] Vitest Mock Chrome API 并验证：已有目录自动归档、缓存/规则预匹配、无目录建议、用户确认、用户拒绝、缺少 Key、AI 失败、批量导入抑制、目录删除、重复/并发、Worker 恢复及撤销。
- [ ] 生成的 Manifest 没有静态全站访问；提交内容没有 API Key。

## 技术边界说明

- `chrome.bookmarks.onCreated` 提供节点和 `parentId`，没有说明用户是否接受默认位置或在原生收藏界面主动改选了内置根目录。P0 采用已确认的根目录策略；嵌套用户文件夹是可观察的尊重边界，内置根目录手动选择无法单独识别。
- P1 网页正文和本地知识索引需要额外读取权限/索引设计；本次不申请页面访问权限或读取网页正文。
- WXT 文档是滚动更新的，实际初始化时选择当时稳定版本并锁定 `pnpm-lock.yaml`；不在规划中固定易过期的具体版本号。
