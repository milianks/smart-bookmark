# Cache reuse evidence

## Current constraints

- `services/classifier.service.ts:54-100`: single requests rank their own candidates, hash the expected single request and store only a matching successful actual request.
- `services/classifier.service.ts:103-176`: batches resolve local outcomes, build a shared candidate set, check the exact ordered batch, and cache only an entirely valid matching successful request.
- `lib/ai/prompts.ts:83-86`: independent per-bookmark suggestions coexist with a same-batch topic consistency instruction. Changing batch membership can change the intended decision.
- `lib/ai/openai-compatible.ts:120-137`: single and batch expected requests differ in prompt, tool and token budget. A hypothetical single request is not evidence that a batch result was generated by that single request.
- `.trellis/spec/backend/extension-runtime-contract.md:128-145`: request provenance, whole-batch reuse, credential generation, provider variant and live target requirements must be consciously updated or preserved, not accidentally bypassed.
- `types/domain.ts:231-246` and `lib/storage/repository.ts:102-115`: cache schema and eviction count all stored results, including duplicates between a batch entry and per-item entries. New writes must retain the 200-result and 64-KiB-per-entry bounds.
- Previous task: `.trellis/tasks/archive/2026-10/10-28-classification-cache-invalidation/design.md`. Strict whole-batch context was deliberate; this request revisits that behavior for lower repeated-call cost.

## Resolved decision and implications

The user approved independent classification and cross-path reuse. Remove same-batch topic grouping. A synthetic single identity is a policy alias, not evidence of an actual single request.

Use `rankFolderCandidates` per input, then group identical ordered candidate contexts. Small trees normally share one group; large divergent contexts may require extra calls. This avoids both companion-dependent candidates and repeated per-item folder payloads.

The real provider rejects malformed entries and incomplete/duplicate indexes before returning (`lib/ai/openai-compatible.ts:164-180`). Preserve that boundary. Salvage validated members only when the returned array can be mapped reliably, such as another member failing target validation.

The repository counts results duplicated in batch and single entries toward the same limit. Preserve that budget; prefer related writes through one repository update.
