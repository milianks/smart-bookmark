# 书签摘要与标签

## Goal

让用户按需为现有书签生成可持久化摘要与标签，并在弹窗与 Review 界面查看；生成过程不改变书签或文件夹。

## Confirmed Facts

- 当前分类 Provider 已支持多协议调用；分类提示包含标题、URL、域名、当前文件夹和文件夹摘要。
- 摘要/标签所需 Provider 调用、严格解析、本地缓存和 `chrome.storage.local` 状态持久化必须留在后台服务层；UI 经 runtime messages 取状态。
- 扩展不读取网页正文，没有 `scripting` 或静态网站 host 权限。
- 摘要/标签输入仅使用书签标题、URL、域名及当前文件夹路径；生成由用户显式触发，包括重新生成。

## Requirements

- 在后台维护按书签 ID 索引的可选摘要和标签元数据；旧版状态缺少该字段时安全归一化。
- 用户能从弹窗最近书签卡片及 Review 书签详情手动生成或重新生成摘要/标签。
- 复用当前 Provider 协议、配置和 origin 权限，但使用独立提示与严格输出 schema；对摘要长度、标签数量/长度设上限，拒绝额外字段及无效输出。
- 仅在成功验证后写入元数据；失败、无效输出或权限缺失时保留已有元数据。
- 持久化结果在后台 worker 重启和重新打开界面后仍可见；不持久化 API key、原始 Provider 响应或未受限输入。
- 单个书签的重复/并发生成须防止竞争覆盖；成功重新生成仅替换所选书签元数据。
- 生成不得移动、创建、删除或重命名书签/文件夹，不得改变分类、扫描、Review 审批、撤销行为。
- 不增加网页正文读取、网页 host 权限或新依赖；Provider 网络权限仍限于用户配置的 origin。

## Acceptance Criteria

- [x] 用户可在 Popup 对最近书签手动生成摘要和标签，并对已有结果重新生成。
- [x] Review 界面可查看对应书签元数据，页面重开/worker 重启后仍存在。
- [x] 仅发送标题、URL、域名、文件夹路径；无网页抓取或新增网页权限。
- [x] Provider 输出严格校验且有界；Provider 失败、权限缺失或输出无效时现有元数据保持不变，并显示可理解错误。
- [x] 同一书签重复/并发请求不会产生重复写入或旧请求覆盖新成功结果；不同书签可独立处理。
- [x] 生成路径不调用任何书签/文件夹变更 API；现有 P0/P1 行为保持不变。
- [x] 测试覆盖 schema 边界、提示输入隐私、权限/Provider 失败、持久化归一化、并发、UI runtime 合约及零书签变更。

## Out of Scope

- 网页正文/DOM 抓取、浏览历史、语义搜索、知识库问答、多 Provider、跨设备同步。
- 无用户操作的自动生成或批量生成。
- 编辑或删除用户书签标题、URL、文件夹，以及用户手工撰写的摘要/标签。

## Key Decisions

- 来源：仅书签元数据，不读取网页内容。
- 触发：用户显式手动生成/重新生成，不自动调用 Provider。
- 保存：本地持久化；仅 schema 验证成功后原子替换该书签记录。
