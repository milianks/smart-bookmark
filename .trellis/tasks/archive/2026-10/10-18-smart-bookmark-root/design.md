# 技术设计：智能书签专属目录

## 1. 目标与边界

在现有 Background Service Worker、`BookmarkPort`、`StateRepository` 和 `OrganizerService` 上增加一个 Chrome 原生书签根目录边界。扩展只处理该根目录及其后代，所有根外书签在事件入口、历史扫描、手动元数据生成和移动前校验处被拒绝。

继续使用现有 AI 分类、规则分类、缓存、Review、撤销、重试和历史扫描流程。分类输入只包含标题、URL、域名、当前目录和专属根目录内的实时文件夹清单。

## 2. 初始化与持久化

1. 在 `wxt.config.ts` 增加 `identity.email`。
2. Background 初始化时调用 `chrome.identity.getProfileUserInfo()`。
3. 取 `email` 的 `@` 前本地部分并 `trim()`；空值、异常或未登录统一回退为 `bookmark`。根目录标题为“`<名称> 的智能书签`”。
4. 在 `bookmarks-bar` 根下查找已保存且可编辑的根目录 ID；ID 失效时按当前标题查找唯一匹配的直接子目录；仍不存在才创建。
5. 新根目录创建在书签栏下，并创建一次性的一级默认布局：

   `📥 待分类`、`💼 工作`、`🚀 项目`、`🧑‍💻 开发`、`📚 学习`、`🔬 研究`、`📰 阅读`、`🛠️ 工具`、`🎨 灵感`、`🌿 生活`、`🗄️ 归档`。

6. 将根目录 ID 和初始化完成标记写入现有 `PersistedState`。初始化失败只记录受限错误并保留 Chrome 已经完成的书签保存，后续启动重试。
7. 已存在的根目录不重新创建、重命名或恢复被用户删除/改名的子目录；初始化完成后用户目录结构完全由 Chrome 原生书签树负责。

## 3. 书签树边界

扩展在 `ChromeBookmarkService` 内增加基于当前树的边界查询：

- 判断节点是否为保存根目录本身或其后代；
- 从根目录递归生成文件夹摘要、路径和可用目标；
- 验证目标文件夹属于该根目录子树且不是 managed 节点；
- 在根目录子树内枚举历史 HTTP(S) 书签。

不再把整棵 Chrome 书签树传给分类器。`getFolders()` 的调用点改为传入当前智能根目录 ID，或使用等价的受限查询。

`forceOrganize` 旧设置字段保留用于读取旧版本状态，但不再扩大处理范围；设置页移除会误导用户的“整理自建文件夹”开关，所有整理范围固定为智能书签根目录。

## 4. 实时分类数据流

```text
onBookmarkCreated
  -> 读取持久化根目录 ID
  -> 校验新书签 parentId 在根目录子树内
  -> 持久化 job（原有队列）
  -> 重读书签位置和根目录内文件夹
  -> 发送标题/URL/域名/当前目录 + 受限目录清单
  -> 校验 AI 返回的目标仍在根目录内
  -> 写入 pendingOperation
  -> 再读书签、设置、目标目录
  -> chrome.bookmarks.move()
```

如果根目录不存在、书签被移出根目录、目标被删除/改名/托管，任务失败或跳过，书签保留原位。AI 请求失败继续使用现有重试与失败状态，不影响原始保存。

## 5. Review、新目录与手动操作保护

- `move` 结果只能指向实时根目录子树内的非 managed 文件夹。
- `suggest_folder` 的 `parentId` 必须实时属于根目录子树；审批时再次检查，才允许在该父目录下创建新目录。
- 分类等待期间比较任务快照 `parentId` 与实时书签位置；用户手动移动后标记跳过/过期，不覆盖用户操作。
- Review 审批、自动移动、撤销和 Service Worker 恢复均复用同一根目录目标验证。

## 6. 历史扫描与元数据

历史扫描只从专属根目录递归枚举可整理 HTTP(S) 书签，移除现有“扫描整个内置根目录/force 模式”的行为。历史审批、批量撤销继续使用现有 live-state 检查。

手动摘要/标签生成也必须先验证书签在智能根目录内，避免根外标题和 URL 被发送给 AI。

## 7. 兼容与回滚

- 旧 `chrome.storage.local` 状态缺少新字段时按未初始化处理，不破坏已有设置、任务、Review 和缓存。
- 根目录初始化失败不会删除、移动或重命名任何现有根外书签。
- 若新边界校验拒绝旧任务，任务进入失败/跳过状态，Chrome 书签保持原位；不做自动迁移。

## 8. 验证重点

- 单元测试覆盖账号名回退、初始化幂等、默认布局、根内/根外判定、目标校验和历史枚举。
- Organizer、Scan、BookmarkMetadata、Repository 现有测试更新为智能根目录模型。
- 完成 `pnpm typecheck`、`pnpm test --run`、`pnpm build`；Chrome 手工验证覆盖首次安装、无登录、重复启动、根外书签和手动移动竞态。
